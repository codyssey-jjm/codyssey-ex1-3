# Mini NPU Simulator

외부 라이브러리 없이 반복문으로 MAC(Multiply-Accumulate) 연산을 수행하고, 입력 패턴이 Cross와 X 중 어느 필터에 더 가까운지 판정하는 Python 콘솔 프로그램이다. 3×3 사용자 입력, `data.json` 일괄 분석, 크기별 성능 측정을 지원한다.

## 실행 환경

- Python 3.8 이상
- 외부 라이브러리 사용 안 함
- `main.py`와 `data.json`이 프로젝트 루트에 있는 상태에서 실행

```bash
python3 main.py
```

환경에 따라 다음 명령을 사용할 수도 있다.

```bash
python main.py
```

프로그램을 실행하면 다음 두 가지 모드 중 하나를 선택할 수 있다.

```text
=== Mini NPU Simulator ===

[모드 선택]
1. 사용자 입력 (3×3)
2. data.json 분석
선택:
```

## 모드 1: 사용자 입력

`1`을 선택하면 3×3 필터 A와 B, 판정할 3×3 패턴을 한 줄씩 입력한다. 각 줄에는 숫자 3개를 공백으로 구분해 입력해야 한다.

다음은 필터 A에 Cross, 필터 B와 입력 패턴에 X를 넣는 예시이다.

```text
필터 A
0 1 0
1 1 1
0 1 0

필터 B
1 0 1
0 1 0
1 0 1

패턴
1 0 1
0 1 0
1 0 1
```

실행 결과는 다음과 같다. 연산 시간은 실행할 때마다 달라질 수 있다.

```text
A 점수: 1.0
B 점수: 5.0
판정: B
연산 시간(평균/10회): 0.008867699943948537 ms
```

행의 숫자가 3개가 아니거나 숫자로 변환할 수 없는 값을 입력하면 안내 문구를 출력하고 같은 행을 다시 입력받는다.

```text
입력 형식 오류: 각 줄에 3개의 숫자를 공백으로 구분해 입력하세요.
```

## 모드 2: data.json 분석

`2`를 선택하면 `data.json`의 5×5, 13×13, 25×25 필터와 패턴을 불러온다. 패턴 식별자에서 크기 N을 추출해 `size_N` 필터를 선택하고, 각 케이스의 행렬과 라벨을 검증한 뒤 Cross/X 점수와 PASS/FAIL을 출력한다.

현재 `data.json`을 실행한 결과는 다음과 같다.

| 케이스 | Cross 점수 | X 점수 | 판정 | expected | 결과 |
|---|---:|---:|---|---|---|
| `size_5_1` | 0.9 | 0.8999999999999999 | UNDECIDED | X | FAIL |
| `size_5_2` | 8.9 | 0.1 | Cross | Cross | PASS |
| `size_13_1` | 0.3 | 14.700000000000008 | X | X | PASS |
| `size_13_2` | 7.499999999999997 | 7.5 | UNDECIDED | Cross | FAIL |
| `size_25_1` | 4.9 | 4.899999999999999 | UNDECIDED | X | FAIL |
| `size_25_2` | 52.9 | 0.1 | Cross | Cross | PASS |

```text
총 테스트: 6개
통과: 3개
실패: 3개
```

한 케이스에서 스키마 또는 크기 오류가 발생하더라도 해당 케이스만 FAIL로 기록하고 다음 케이스 분석을 계속한다.

## 구현 요약

### MAC 연산

패턴과 필터의 같은 위치에 있는 값을 곱한 뒤 모두 더하여 점수를 계산한다.

```text
score = Σ(pattern[row][column] × filter[row][column])
```

MAC 연산은 NumPy 같은 벡터화 라이브러리 없이 이중 반복문으로 구현했다. 패턴과 필터는 비어 있지 않은 정사각형이어야 하며 두 행렬의 크기도 같아야 한다.

### 라벨 정규화

JSON에서 사용하는 서로 다른 라벨을 프로그램 내부의 표준 라벨로 변환한다.

| 입력 라벨 | 표준 라벨 |
|---|---|
| `+`, `cross` | `Cross` |
| `x` | `X` |

MAC 판정, `expected` 비교 및 콘솔 출력은 표준 라벨인 `Cross`와 `X`를 기준으로 수행한다.

### epsilon 동점 정책

두 점수의 차이가 다음 조건을 만족하면 부동소수점 표현 차이로 보고 동점으로 처리한다.

```python
abs(cross_score - x_score) < 1e-9
```

동점의 표준 판정은 `UNDECIDED`이다. 판정이 `Cross` 또는 `X`이고 `expected`와 같을 때만 PASS이므로, `UNDECIDED`는 현재 JSON의 Cross/X 정답과 비교하면 FAIL이 된다.

### JSON 검증과 오류 격리

- 패턴 키가 `size_{N}_{idx}` 형식인지 확인한다.
- 패턴의 `input`과 `expected` 필드가 있는지 확인한다.
- 패턴 크기에 해당하는 `size_N` 필터가 있는지 확인한다.
- 패턴과 필터가 N×N 정사각형 숫자 배열인지 확인한다.
- Cross와 X 필터가 모두 있는지 확인한다.
- 검증 오류는 식별자와 사유를 포함한 케이스별 FAIL로 기록한다.

## 성능 분석

각 크기의 MAC 함수 호출 구간만 `time.perf_counter()`로 측정한다. 파일 읽기와 콘솔 입출력 시간은 포함하지 않으며, 각 방식을 10회 실행한 전체 시간을 10으로 나누어 1회 평균 시간을 구한다.

다음 표는 2026-08-13 실행에서 측정된 예시이다. 운영체제, 하드웨어 상태 및 실행 시점에 따라 시간은 달라질 수 있다.

| 크기 | 2차원 평균(ms) | 1차원 평균(ms) | 연산 횟수 |
|---:|---:|---:|---:|
| 3×3 | 0.002 | 0.001 | 9 |
| 5×5 | 0.003 | 0.001 | 25 |
| 13×13 | 0.011 | 0.008 | 169 |
| 25×25 | 0.041 | 0.030 | 625 |

## 결과 리포트

1. 현재 `data.json`의 6개 케이스 중 3개가 PASS이고 3개가 FAIL이다.
2. `size_5_1`은 Cross 점수 0.9와 X 점수 0.8999999999999999의 차이가 `1e-9`보다 작아서 `UNDECIDED`로 판정되었다.
3. `size_13_2`도 두 점수 7.499999999999997과 7.5의 차이가 허용오차보다 작아서 `UNDECIDED`로 판정되었다.
4. `size_25_1` 역시 4.9와 4.899999999999999의 차이가 허용오차보다 작아서 `UNDECIDED`로 판정되었다.
5. 세 케이스의 `expected`는 Cross 또는 X이므로 `UNDECIDED`와 일치하지 않아 FAIL이 되었다.
6. 이 세 실패는 JSON 키, 라벨 또는 행렬 크기 오류가 아니라 부동소수점 점수 비교 정책에 따른 결과이다.
7. epsilon 없이 단순히 더 큰 점수만 선택하면 계산 과정에서 생긴 매우 작은 표현 차이를 의미 있는 우세로 잘못 판단할 수 있다.
8. `+`와 `cross`를 `Cross`로, `x`를 `X`로 정규화하기 때문에 서로 다른 외부 라벨 표기가 PASS/FAIL 비교를 방해하지 않는다.
9. N×N MAC은 모든 위치를 한 번씩 방문하므로 한 번의 계산에서 곱셈과 누적을 N²번 수행한다.
10. 따라서 3×3, 5×5, 13×13, 25×25의 연산 횟수는 각각 9, 25, 169, 625로 증가한다.
11. 입력 크기 N에 대한 MAC 연산의 시간 복잡도는 `O(N²)`이며, 실제 측정에서도 행렬이 커질수록 평균 실행 시간이 대체로 증가했다.
12. 측정 시간은 매우 짧아 운영체제 스케줄링과 실행 환경의 영향을 받으므로 한 번의 측정값보다 연산 횟수와 반복 측정의 전체 경향을 함께 봐야 한다.

## 보너스 구현

### 1차원 MAC 성능 비교

2차원 패턴과 필터를 행 순서대로 길이 N²의 1차원 리스트로 변환하고, 하나의 반복문으로 MAC 점수를 계산한다. 배열 변환 시간은 준비 시간으로 보고 측정 구간에서 제외했다. 기존 2차원 방식과 1차원 방식은 같은 입력으로 각각 10회 실행하며, 두 방식의 점수가 같은지도 확인한다. Python 실행 환경에서는 1차원 방식이 항상 더 빠르다고 보장할 수 없으므로 실제 측정값을 그대로 비교한다.

### Cross/X 패턴 생성기

크기 N을 전달하면 N×N Cross와 X 패턴을 반복문으로 생성한다. Cross는 가운데 행과 열을 `1.0`으로 만들고, X는 양쪽 대각선을 `1.0`으로 만든다. 생성 결과는 기존 `Matrix` 형식이므로 MAC 함수에서 바로 사용할 수 있으며, 성능 분석의 3×3 Cross 패턴과 필터 생성에 재사용한다.

## 재현성 확인

- 모드 1에 위의 Cross 필터, X 필터, X 패턴을 입력하면 A 점수 1.0, B 점수 5.0, 판정 B가 출력된다.
- 모드 1에서 숫자가 2개인 행을 입력하면 오류 문구가 출력되고 같은 행을 다시 입력받는다.
- 모드 2에서 현재 `data.json`을 분석하면 총 6개, 통과 3개, 실패 3개가 출력된다.
- JSON 케이스의 행렬 크기가 식별자의 N과 다르면 해당 케이스는 사유가 포함된 FAIL로 처리되고 다음 케이스 분석은 계속된다.
